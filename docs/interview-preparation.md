# 면접 준비 기능

## 사용 흐름

### 구직자

1. `/new-project`에서 JD를 입력하면 서류 등록 전에 JD 기반 기본 질문 6개가 보입니다.
2. 서류 분석을 마치면 `/projects/[id]/my-analysis` 상단에서 공통 질문 3개와 개인별 질문 4개를 바로 확인합니다.
3. 질문 이유, JD 문장, 지원서의 실제 파일·페이지·원문, 답변 준비 가이드를 확인합니다.
4. 연습 메모를 입력하고 **저장**을 누릅니다. 질문마다 준비 완료를 체크할 수 있습니다.

### 채용담당자

1. `/projects/[id]/applicants`에서 지원자를 열고 **면접 준비 → 면접 대상으로 선택**을 누릅니다.
2. 선택한 지원자에 대해서만 질문을 생성합니다. 지원자 알림은 발송하지 않습니다.
3. 같은 JD의 공통 질문 3개는 기본 생성 시 동일합니다. 개인별 질문 4개는 핵심 근거 미확인 항목부터 확인합니다.
4. 질문을 수정·저장, 이동, 삭제할 수 있습니다. 직접 수정한 공통 질문은 ‘직접 수정’으로 표시됩니다.
5. **질문지 확정 → 면접 완료로 표시**로 진행하고, 필요하면 다시 준비 상태로 열 수 있습니다.
6. 면접관 메모와 ‘아직 질문 전 / 구체적 사례 확인 / 일부 확인 / 추가 확인 필요’를 별도로 저장합니다.
7. 질문·메모 복사 또는 인쇄용 보기로 내보냅니다. 인쇄용 출력은 HTML을 해석하지 않고 일반 텍스트로 표시합니다.

질문 재생성은 명시적 버튼으로만 실행합니다. 직접 수정한 질문, 기존 순서, 삭제한 질문의 제외 상태, 저장한 메모는 유지합니다. 질문 문구가 바뀌면 해당 질문의 준비/확인 상태는 초기화합니다. 질문 전체를 다시 구성하려면 새 분석 회차를 사용합니다.

## 저장과 경계

- 기존 브라우저 저장소 `wantedhacker-projects-v1`의 프로젝트에 선택 필드 `interviews`를 추가했습니다. 과거 데이터는 그대로 읽습니다.
- 질문 묶음은 `interview-v1:revisionId:analysisId`로 구분합니다. 재방문은 저장한 묶음을 사용하고 재분석은 새로운 묶음을 생성합니다.
- 소유자·역할·분석 회차·지원자 분석 ID를 검사하고, 묶음 버전으로 오래된 화면의 덮어쓰기를 거부합니다.
- 재분석 저장과 면접 메모 저장이 겹쳐도 최신 면접 메모를 보존합니다. 면접 기능은 서류 분석 결과나 점수를 변경하지 않습니다.
- 구직자 연습 메모와 채용담당자 질문·메모는 서로 다른 소유 프로젝트에 저장됩니다. 생성 요청에는 점수, 배점, 이름, 생년월일 및 메모 필드를 넣지 않습니다. 원문 자체에 개인정보가 포함되어 있다면 관련 발췌문에 포함될 수 있습니다.
- 현재는 **브라우저 로컬 데모**입니다. 화면상의 역할 분리는 실제 서버 인증/인가나 기기 간 동기화를 제공하지 않습니다. 같은 브라우저 저장소에 접근 가능한 사람에게서 데이터를 보호하는 보안 경계가 아닙니다.

## AI 연결

기본값은 규칙 기반 질문이며 화면에 **기본 질문**으로 표시됩니다. JD 입력 중 미리보기는 항상 기본 질문을 사용합니다.

`.env.local`(로컬 Next 실행) 또는 `.env`(Docker Compose)에 서버 전용 환경 변수를 설정합니다.

```dotenv
INTERVIEW_AI_ENABLED=true
OPENAI_API_KEY=<API 키>
OPENAI_INTERVIEW_MODEL=<Structured Outputs를 지원하는 사용 가능한 모델 ID>
```

Docker는 `docker compose up -d --force-recreate web`으로 환경을 반영합니다. 키를 `NEXT_PUBLIC_` 변수에 넣거나 소스에 커밋하지 마세요.

`POST /api/interviews`는 직무 기준과 검증된 발췌문만 받아 OpenAI Responses API를 호출합니다. [공식 Structured Outputs 형식](https://developers.openai.com/api/docs/guides/structured-outputs)을 사용하며 `store: false`, 25초 제한을 적용합니다. 모델이 반환한 질문 ID·개수·형식을 검사합니다. 원문·파일·페이지·질문 이유는 모델이 만들지 않고 입력에서 직접 연결합니다. 다만 질문 문장 자체는 AI 초안이므로 내용 검토가 필요합니다.

- 채용담당자의 공통 질문은 AI가 수정하지 않습니다.
- 키/모델 미설정 시 외부 호출 없이 기본 질문을 반환합니다.
- 거부, 오류, 시간 초과, 잘못된 응답은 기본 질문으로 전환하며 원래 분석은 계속 표시합니다.
- API는 JSON 입력, 180KB 요청 크기, 요청 출처, 프로세스당 분당 20회/동시 3회를 검사합니다.
- **실서비스 공개 전에는 서버 인증·프로젝트 소유권 검증·공유 요청 제한·DB 저장을 연결해야 합니다.** 현재 브라우저 제출 데이터를 서버 DB 원본과 대조할 수 없으므로 유료 AI 설정은 로컬 테스트 용도입니다. Compose는 127.0.0.1에만 포트를 공개합니다.

## 검증

`tests/interviews.test.ts`에서 생성 개수, 원문 검증, 공통 질문 일관성, 소유자/역할/버전 검사, 메모 보존, 과거 데이터 호환, AI 응답과 오류 처리, 요청 검증 및 텍스트 내보내기를 검사합니다. AI 공급자 검증은 모의 응답을 사용하며 실제 API 키를 사용하는 호출 검증과 구분합니다.

### 이번 구현의 확인 결과

- 단위/회귀 테스트 65개 통과, lint·타입 검사 및 프로덕션 Docker 빌드 통과.
- `scripts/test-synthetic-resumes.ts`로 실제 웹 API + Kotlin 서버에서 백엔드·프론트엔드·PM 가상 이력서의 기존 분석 결과를 검증하고, 각 직무의 구직자/채용담당자 질문 7개와 원문 근거를 확인했습니다(면접 준비 6개 조합).
- 브라우저에서 JD 미리보기, 분석 결과 자동 질문 표시, 면접 대상 선택, 면접관 메모, 확인 상태, 질문지 확정, 구직자 연습 메모/준비 완료, 재생성 및 새로고침 후 저장 유지 확인.
- 실제 OpenAI API 호출과 인쇄 장치 출력은 검증하지 않았습니다. 공급자 성공/오류/거부/형식 오류 처리는 모의 응답 테스트로 검증했습니다.
