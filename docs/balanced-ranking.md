# 핵심 항목과 균형순 비교

## 사용 방법

1. 새 프로젝트에서 직무와 JD를 입력한다.
2. **추출한 평가 기준 확인**을 펼쳐 중요한 항목의 **핵심 항목**을 선택한다. 필수 자격 문구만으로 자동 지정하지 않는다.
3. 항목별 충족 기준을 25%, 50%, 75%, 100% 중 선택한다. 기본값 50%는 직접 수행 역할 이상의 근거다.
4. 지원자를 분석하면 목록에 종합점수, 핵심 충족 수, 전체 항목 충족률, 추가 확인 항목과 판정 불가 항목이 함께 표시된다.
5. 기본 **균형순** 외에 **종합점수순**, **특정 역량 중심**, **최근 등록순**으로 전환할 수 있다.

## 계산 규칙

- 항목 수준: 미확인 0%, 언급/학습 25%, 직접 수행 역할 50%, 역할+판단 75%, 역할+판단+결과 100%.
- 기술 직무도 동일한 단계로 평가한다. 직접/연관 키워드 여부는 별도로 보존하며 기술 이름만으로 만점을 주지 않는다.
- 항목 충족: 근거 수준의 비율이 설정한 최소 비율 이상. 소수점 점수 반올림으로 판정이 바뀌지 않도록 원래 단계를 사용한다.
- 전체 충족률: 충족 항목 수 ÷ 전체 항목 수. 항목 배점과 무관하게 항목당 한 개로 계산한다.
- 균형순: 핵심 충족 수 내림차순 → 전체 충족 항목 수 내림차순 → 총점 내림차순. 동률은 이름과 지원자 ID로 안정적으로 정렬한다.
- 핵심을 지정하지 않았으면 전체 항목 충족률부터 비교한다. 핵심 미충족에 대한 자동 탈락 처리는 없다.
- 특정 역량순은 해당 항목의 배점 대비 근거 비율을 먼저 비교한다.
- 미기재/낮은 단계는 추가 확인, 읽지 못한 서류 또는 항목 점수가 없는 과거 기록은 판정 불가로 구분한다. 판정 불가는 충족 수에 더하지 않으며 분모에는 남겨 불완전한 서류의 충족률이 부풀려지지 않게 한다.
- 전체 판독 불가는 점수 기반 정렬에서 마지막에 둔다. 부분 판독이면 확인한 근거로 비교하고 판정 불가 항목을 별도 표시한다.

예: 4개 항목에서 `100·100·50·0%`인 지원자는 충족률 75%, `75·50·50·50%`인 지원자는 충족률 100%다. 핵심 조건이 같다면 총점이 낮더라도 후자가 균형순에서 먼저 보인다. 특정 분야 강점은 종합점수순/역량순으로 함께 검토한다.

## 기존 기록 및 버전

- 분석 엔진은 `experience-keywords-v4`다. 기술 직무가 근거 단계 방식으로 변경되어 새 점수는 이전 이진 방식보다 낮아질 수 있다.
- JSON의 기술 직무 모드는 `technical-evidence`, 나머지는 `evidence`다. 키워드 관계 자체는 같으므로 목록 식별자는 `job-profiles-v1`을 유지한다. 규칙 버전은 결과의 evaluatorVersion으로 구분한다.
- 과거 결과의 점수·근거는 재계산하지 않는다. 단계 정보가 없는 기록은 저장된 점수 비율로 표시하고 ‘이전 키워드 방식’이라고 안내한다. 항목 점수조차 없는 기록은 충족률 산출 불가로 표시한다.
- 핵심/최소 기준은 프로젝트에 저장하며 같은 프로젝트 재분석에서 변경할 수 없다. 기준을 바꾸려면 새 프로젝트를 만든다. 재분석은 현재 서버 규칙으로 새 버전을 추가하고 이전 버전은 보존한다.
- 이 지표는 작성된 근거의 규칙 판독이다. 실제 역량 검증이나 합격/탈락 결정은 하지 않는다.

## 검증

- 집중형보다 균형형이 먼저 보이는 경우, 핵심 항목 우선, 역량별/총점 정렬, 미판독 처리, 반올림 경계, 기존 기록 보존을 자동 테스트한다.
- 서버에서 기술 동의어 연결을 유지하면서 단순 언급·직접 수행·판단·결과를 구분하고, 부정/학습 문장과 다른 문장의 성과를 제외하는지 검증한다.
