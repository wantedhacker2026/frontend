# 12개 직무별 지원서 평가 목록

목록 버전: `job-profiles-v1` · 12개 직무 · 86개 항목 · 799개 기본 키워드/연관 표현(항목 간 중복 포함, 키워드별 제한 관계 별도)

## 사용 방법

새 프로젝트에서 **분석 직무**를 선택하고 JD를 입력한다. 선택한 직무의 **세부 평가 목록**에서 전체 항목·기본 배점·키워드·연관 경험을 열람할 수 있다. 실제 분석에는 JD에 언급된 항목만 추출한다. 직무를 변경하면 편집한 평가 기준도 새 직무와 JD를 기준으로 다시 만든다. 목록 밖 조건은 평가 기준 추가로 입력할 수 있다. 기존 프로젝트는 직무와 기준을 바꾸지 않고 새 분석 버전을 추가한다. 다른 직무를 적용하려면 새 프로젝트를 만든다.

직무를 선택하지 않은 과거 프로젝트와 공통 키워드 분석은 기존 흐름을 유지한다. 직무를 선택한 프로젝트는 채용담당자와 구직자 모두 서버 판정을 사용한다.

## 점수 계산

- 12개 직무 모두 키워드로 찾은 원문의 근거 수준을 0~4로 분류하고 `배점 × 수준 / 4`로 계산한다. 기술 직무는 기술 동의어·연관 관계를 유지한다.
- 기본 배점의 합계는 직무마다 100점이다. JD에 해당하는 항목만 선택되면 배점을 다시 100점으로 환산한다. 직접 추가한 기준의 기본 배점은 10이다.
- 점수는 소수 첫째 자리까지, 총점은 반올림한다. 같은 경험의 반복 기재는 가산하지 않는다.
- 연관 키워드 O와 근거 수준은 별개다. 도구명만 있으면 연관 O여도 1단계(25%)이며 추가 확인으로 표시한다.
- 읽지 못한 서류는 판독 불가로 유지한다. 낮은 점수나 미확인은 역량 부재나 자동 탈락을 의미하지 않는다.

| 근거 수준 | 반영률 | 규칙 판독 기준                                                              |
| --------- | -----: | --------------------------------------------------------------------------- |
| 0 미확인  |     0% | 관련 긍정 근거 없음                                                         |
| 1 언급    |    25% | 도구·경험 언급 또는 학습·예정                                               |
| 2 역할    |    50% | 담당·책임·주도·수행 등의 역할 표현                                          |
| 3 판단    |    75% | 역할과 함께 조정·선택·합의·우선순위 등의 판단 표현                          |
| 4 결과    |   100% | 역할·판단에 수치와 결과 표현 또는 고객 검수 통과·오픈일 준수 등의 결과 표현 |

근거 수준은 일치하는 원문 한 문장/행 안에서 규칙으로 분류한다. 다른 문장의 성과를 가져와 점수를 올리지 않는다. 복잡한 문맥·본인과 팀의 기여를 완전히 구별할 수 없으며, 지원서 주장의 진위를 검증하지 않는다. 10년 경력·자격증 유효성·특정 버전·규제 충족 등은 이 점수로 확정하지 않고 별도 확인한다.

## 코드와 유지보수

- 서버 원본: `03_wantedhacker-server/src/main/resources/analysis/job-profiles.json`
- 웹 사본: `data/evaluation/job-profiles.json`
- 서버 판정: `JobProfileCatalog.kt`, `KeywordAnalysisService.kt`, `EvidenceLevel.kt`
- 웹 직무/배점: `lib/evaluation/job-profiles.ts`
- API: `GET /api/analysis/keywords/profiles`, `POST /api/analysis/keywords`
- 직무 요청은 `jobProfile`, `catalogVersion`, 각 기준의 `catalogCriterionId`를 함께 전달한다. 등록되지 않은 직무/기준은 400, 목록 버전 불일치는 409다.
- 의미가 바뀌면 JSON `version`을 올리고 아래 명령으로 웹 사본을 동기화한다. 웹과 서버를 함께 갱신한다. 과거 분석 결과는 바꾸지 않는다.

```sh
node scripts/sync-job-profiles.mjs ../03_wantedhacker-server
node scripts/sync-job-profiles.mjs ../03_wantedhacker-server --check
```

일반 기술의 동의어·관계는 기존 `ExperienceKeywordCatalog.kt`를 사용한다. PM 등 근거 평가에서는 개발 직무의 일반 범주 관계를 재사용하지 않아, 주문 서버 구현을 PM 요구사항 관리 경험으로 연결하지 않는다. 직무의 상세 연관 목록은 일방향이며 자동 연쇄 확장하지 않는다. `keywordRelations`가 있으면 해당 JD 키워드는 지정한 관계만 적용한다. 예를 들어 보안 경험만으로 금융권 경험을, WBS 언급만으로 품질 관리 경험을 인정하지 않는다.
