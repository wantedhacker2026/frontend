# 와이어프레임 V4 적용 내역

기준: 사용자가 제공한 `와이어프레임_2.pdf` 17쪽(2026-09-14). 기존 프론트엔드 MVP 범위를 유지하면서 역할별 프로젝트 흐름을 기본 진입으로 적용했습니다. 문서에서 색상은 최종 디자인이 아니라고 명시했으므로 wantedhacker의 타이포그래피와 간격, 파란색 강조를 유지했습니다.

## 화면별 적용

| 화면              | 구현 경로 / 동작                                                                                                                                                                           |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| S01 비로그인 홈   | `/` → `/home`. 빈 프로젝트 상태, 프로젝트 생성, 로그인 진입. 현재 홈에서 홈을 누르면 URL·스크롤을 변경하지 않습니다.                                                                       |
| S02 역할별 로그인 | `/login`. 회사 이메일·임의 데모 비밀번호 입력, 데모 가입 전환, 카카오·구글·네이버 데모 버튼. 채용담당자 → `/home`, 구직자 → `/new-project`. 역할 재선택 없음.                              |
| S03 / S03J 홈     | 같은 `/home`에서 로그인 역할에 맞는 ‘프로젝트 리스트’ / ‘채용공고 리스트’. 계정·역할별 목록 필터, 최신 생성순·ID 순 정렬, 고정 제목과 스크롤 목록.                                         |
| S04 / S04R 등록   | `/new-project`. JD 본문 / 공고 URL / JD 이미지 입력, 평가 기준 편집, PDF·TXT 선택 및 드롭, 이름·선택 생년월일·지원자별 묶음 확인. 구직자는 기존에 저장한 지원서 버전도 가져올 수 있습니다. |
| S05 처리          | 중복 실행 잠금, 배경 입력·닫기 차단, JD → 서류 → 저장의 진행 단계. 성공 시 역할에 맞는 결과로 자동 이동.                                                                                   |
| S06 지원자 목록   | `/projects/[projectId]/applicants`. 등록순·이름순 요약 목록, 검색, 서류 추가 등록. 생년월일은 직접 입력한 값만 표시하며 없는 값은 ‘미기재’.                                                |
| S07 내 분석       | `/projects/[projectId]/my-analysis`. JD 핵심 기준, 종합 Match, 기재 O/X, 근거와 상태. 미기재는 능력이나 합격 여부가 아님을 표시.                                                           |
| S08 요약 모달     | 목록 위에서 지원자 분석표와 원문에 기반한 한 줄 요약. 닫으면 목록과 스크롤 유지.                                                                                                           |
| S09 원문 모달     | 상세 위에 근거 원문, 실제 파일명·추출 페이지, 키워드 강조, 페이지의 전체 추출 텍스트. ESC / 바깥 클릭 / 돌아가기 버튼은 한 단계만 닫고 초점 복귀.                                          |
| S10 구직자 첨삭   | 선택 기준의 원문·설명·대괄호 작성 틀과 복사 버튼. 기존 원문을 수정하지 않음. 확인된 검색 결과가 없으므로 공모전·해커톤 링크는 생성하지 않습니다.                                           |
| S11 오류          | 파일별 형식·크기·페이지·암호화·손상·이미지 PDF 오류, 교체·제거, 준비된 서류만 처리. 전체 작업 실패는 입력과 직전 성공 결과를 보존하고 재시도 가능.                                         |

## 재분석과 데이터 보존

- 프로젝트별로 JD와 평가 기준을 고정하고, 성공할 때마다 `ProjectRevision`을 추가합니다. 결과의 버전 선택으로 이전 서류·출처·점수를 다시 조회할 수 있습니다.
- 같은 프로젝트의 처리 도중 다른 분석이 저장됐다면 이전 버전을 덮어쓰지 않고 최신 결과를 확인하도록 안내합니다.
- 기존 `shortlist-demo-v1` 저장 키, 지원서 버전, 지원 이력, 기존 채용 화면은 유지합니다. 프로젝트 데이터는 `wantedhacker-projects-v1`에 별도로 저장합니다.
- 등록 초안은 계정·프로젝트별 `sessionStorage`에 저장합니다. 새로고침하면 입력을 복원하며 처리 중 새로고침한 경우 등록 화면에서 다시 실행할 수 있습니다. 백그라운드 서버 작업 복원은 구현하지 않았습니다.
- 저장 실패 시 성공으로 처리하지 않습니다. 원본 PDF 바이너리는 서버나 브라우저 저장소에 저장하지 않고 파일명·크기·추출 텍스트·페이지·분석을 보존합니다. JD 이미지 미리보기는 현재 탭에서만 유지됩니다.

## 현재 실제로 동작하는 부분과 연동 경계

- **실제 프론트엔드 기능**: 로컬 PDF.js 텍스트 추출, 페이지별 출처, TXT 읽기, 드롭/선택/교체/제거, 프로젝트 및 분석 버전 저장, 모달, 필터, 폼 검증, 저장한 지원서 버전 가져오기.
- **데모 로그인**: 비밀번호는 저장하거나 전송하지 않습니다. 회사 이메일은 로컬 데모 프로필 식별에만 사용합니다. 소셜 버튼 세 개는 같은 구직자 데모 프로필로 진입합니다. 실제 OAuth·회원가입·회사 인증을 수행하지 않습니다.
- **JD URL / 이미지**: 파일명과 참조 주소를 등록하지만 자동 수집과 OCR은 미연동입니다. 사용자가 확인하여 입력한 JD 본문으로만 평가합니다. 주소나 이미지가 있다는 이유만으로 분석된 것으로 표시하지 않습니다.
- **평가**: `CandidateEvaluator`를 사용한 규칙 기반 데모입니다. 문서의 AI 판독 정책은 미정이므로 ‘규칙 판독 · 데모’로 표시하고 자동 불일치 판정을 만들지 않습니다. 모델 호출과 AI 추천 검색은 아직 없습니다.
- **접근 구분**: 새 프로젝트 경로는 로컬 세션의 역할과 소유자에 따라 필터링합니다. 이것은 프론트엔드 동작 검증이며 **보안 경계가 아닙니다**. 실제 배포 서비스에는 서버 인증, 소유권 검사, 파일 저장 접근 제어가 필요합니다. 같은 브라우저 저장소는 개발자 도구로 볼 수 있으므로 실제 개인정보가 담긴 서류를 사용하는 제품 단계가 아닙니다.

## 미정 항목에 적용한 데모 기본값

- 비로그인: 등록 작성 허용, 분석 전 데모 로그인 필요.
- 이름: 미입력 시 ‘지원자’ / ‘채용담당자’ 대체. 제목은 직접 입력하거나 예시 공고에서 채움.
- JD 이미지: PNG/JPG, 10MB 이하. 서류: PDF/TXT, 파일당 10MB, PDF 30페이지, 추출 텍스트 10만 자, 최대 20개.
- 파일 묶음: 파일별 지원자 선택을 제공하며 채용담당자가 묶음을 확인해야 실행됩니다. 이름·생년월일로 자동 병합하지 않습니다.
- 텍스트가 없는 PDF 페이지는 이미지 또는 빈 페이지로 구분 확인하도록 안내합니다. 해당 부분에 의존할 수 있는 미확인 기준은 ‘판독 불가’로 표시합니다.
- 파일 저장·보관 정책, 실제 계정 정책, OAuth 제공자 설정, 작업 큐·시간 제한·재시도 정책, AI 판독 기준, 외부 추천 출처 정책은 서버 연동 시 확정해야 합니다.

## 코드와 교체 지점

- `lib/projects/types.ts`: 사용자, 문서, 출처, 프로젝트, 분석 버전 모델 및 저장 데이터 검증.
- `lib/projects/domain.ts`: 역할별 처리, 근거 연결, 버전 누적, 소유자·동시 저장 확인. `processDraft`의 evaluator 인자는 `CandidateEvaluator` 계약을 사용합니다.
- `lib/projects/documents.ts`: PDF/TXT 읽기. 실제 업로드 API / OCR 구현으로 교체하거나 확장할 위치입니다.
- `lib/projects/store.tsx`: 로컬 데모 저장. 실제 인증·프로젝트 API로 교체할 위치입니다.
- `components/projects/`: 홈, 로그인, 등록, 파일 관리, 분석·중첩 모달, 공통 탐색.
- `app/projects.css`: 프로젝트 화면 전용 반응형 스타일.

PDF 텍스트 추출은 Mozilla의 [PDF.js 공식 사용 예제](https://github.com/mozilla/pdf.js/blob/master/examples/webpack/main.mjs)를 참고하여 같은 배포의 worker로 실행합니다. 외부 CDN으로 서류를 전송하지 않습니다.

## 검증 기록

- 기존 25개 및 프로젝트 도메인 7개: 역할별 처리, 입력 거부, 실제 출처 연결, 부분 실패, 페이지 판독 불가, 원문 기반 요약, 이전 버전 보존, 소유자 필터, 동시 저장 및 실패 시 보존.
- 실제 17페이지 PDF를 로컬 브라우저에 선택하여 텍스트 추출 완료와 페이지 수 표시를 확인했습니다. 파일 선택 자동화 도구의 응답 지연이 있었지만 완료 후 화면에서 추출 성공을 검증했습니다.
- 구직자 로그인 → 등록 → 뒤로가기(구직자 홈) → 예시 분석 → 결과 자동 이동을 확인했습니다. 보강 후 v2 93점, 이전 v1 58점 결과가 각각 유지되었습니다. 점수는 해당 데모 입력에서의 값입니다.
- 채용담당자 로그인 → 빈 담당자 홈 → 20명 예시 등록 → 묶음 확인 후 실행 → 지원자 목록 자동 이동을 확인했습니다.
- 지원자 상세 → Spring 원문 → ESC → 지원자 상세 → ESC → 목록 순서 및 포커스 복귀를 확인했습니다.
- 채용담당자 세션으로 구직자 프로젝트 주소를 열었을 때 접근 불가 화면이 표시됩니다.
- 데스크톱 1200px, 모바일 390px에서 목록과 원문 모달을 확인했습니다.
