# MVP 검증 기록

검증일: 2026-09-11. 로컬 브라우저 데모 데이터만 사용했습니다.

## 자동 검증

- `npm test`: 도메인 테스트 15개 통과
- `npm run typecheck`: TypeScript strict 검사 통과
- `npm run lint`: ESLint 검사 통과
- `npm run build`: Next.js Webpack 프로덕션 빌드 통과
- `npm run format:check`: 코드 포맷 검사 통과

독립적인 외부 AI·DB·결제·이메일 연동 테스트는 해당 기능이 이번 구현 범위에 없으므로 수행하지 않았습니다.

## 환경 이슈와 해결

- 제한된 셸에서 개발 서버의 포트 바인딩이 차단되어 필요한 실행 권한으로 로컬 서버를 시작했습니다.
- Turbopack 프로덕션 빌드의 프로세스 통신 오류는 Webpack 빌드를 사용해 해결했습니다.
- tsx CLI의 임시 IPC 제한은 `node --import tsx --test` 실행 방식으로 해결했습니다.
- 개발 중 설정 파일이 변경될 때 서버 재시작 및 Fast Refresh가 발생했습니다. 재시작 후 페이지를 다시 확인했습니다.

## 수동 재검증 절차

1. 데모 초기화 후 `/recruiter/jobs/backend/candidates`에서 필터와 정렬을 변경합니다.
2. 2~3명 비교, 상세 원문 펼치기, 검토 상태 변경 후 새로고침합니다.
3. `/jobs/backend/apply`에서 예시를 채우고 제출합니다.
4. 개선 계획에서 가이드를 열고 완료 체크, 새로고침, 지원서 재분석을 수행합니다.
5. `/recruiter/jobs/new`에서 새 공고를 등록합니다. 총 배점이 100이 아닌 경우 저장이 차단되어야 합니다.
6. 모바일 화면 크기에서 공고, 지원서 폼, 결과와 개선 계획을 탐색합니다.
7. 테스트를 마치면 데모 이용 가이드의 초기화 기능으로 원래 데이터로 돌아갑니다.

추가 확인: Kotlin + 3년 이상 복합 필터는 강하늘·이서준 2명을 표시했고, 이름순 정렬이 반영되었습니다. 검색 결과가 없을 때 초기화 버튼이 동작했습니다. 공고 목록·상세·지원 폼·분석 결과·개선 계획·채용담당자 지원자 목록의 6개 경로를 390×844에서 확인했으며 가로 넘침이 없었습니다. 검증 후 초기화 기능으로 3개 공고와 20개 지원서를 복원했습니다.

## 지원서 버전 관리 추가 검증

- 도메인 테스트 총 24개 통과. 버전 복제·수정의 독립성, 선택된 버전의 평가 반영, 원본 삭제 후 제출 기록 보존, v1 저장 데이터 이전, 유효하지 않은 입력 거부를 확인했습니다.
- TypeScript, ESLint, Next.js 프로덕션 빌드 통과. 신규 `/resumes`, `/resumes/new`, `/resumes/[resumeId]/edit` 경로를 확인했습니다.
- 브라우저에서 기본형을 저장하고 복제한 뒤 Kafka/Redis/AWS/트래픽 경험을 보강한 버전을 별도로 저장했습니다.
- 강조형을 선택해 Backend 공고에 지원했을 때 92점, 기본형은 73점으로 서로 다른 분석 결과가 생성됐습니다.
- 강조형 원본의 이름과 프로젝트 내용을 수정한 뒤 원본을 삭제해도, 내 지원 현황과 기존 결과에는 최초 버전 이름·수정 번호·92점 결과가 유지됐습니다.
- 공고의 ‘새로 작성 → 예시 채우기 → 버전만 저장’에서 새 버전이 즉시 선택됐고, 이어서 지원·분석이 완료됐습니다.
- 새 브라우저 탭으로 목록을 다시 열었을 때 저장한 버전 2개가 유지됐습니다.
- 584px 화면에서 지원서 선택·분석 결과의 가로 넘침이 없었고, 1280px 목록에서 제목·기술·수정·복제·삭제·지원 CTA를 확인했습니다.
- 지원서 입력은 로컬 브라우저의 테스트 데이터만 사용했습니다. 실제 기업 전송이나 서버 저장은 없습니다.

## Framer 서류 분석 화면 검증 (2026-09-14)

- 기존 도메인 테스트 24개, ESLint, TypeScript와 프로덕션 빌드를 통과했습니다.
- 샘플 분석에서 전체 10개 / 근거 확인 6개 / 보완할 항목 4개 필터를 확인했습니다. Kafka 상세 모달에서 미확인 이유, 실천 가이드 모달, 다른 지원서 버전 선택으로 이동했습니다.
- 저장된 기본형 v1을 선택해 새로 제출했고, 73점 결과와 제출 버전 표기가 새 분석 화면에 표시됐습니다. 테스트 입력은 로컬 브라우저의 기존 데모 지원서를 사용했습니다.
- 채용담당자 상세에서 내부 점수 열과 Spring 근거 모달의 12.8 / 15를 확인했습니다. 지원자 화면에는 내부 점수 열이 없습니다.
- 1280px 데스크톱과 390px 모바일에서 문서 가로 넘침이 없었습니다. 모바일 표는 카드로 전환되고 상세 모달 폭은 358px입니다.
